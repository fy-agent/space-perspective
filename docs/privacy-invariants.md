# 隐私与文件边界

这些边界描述当前实现，各开发入口的能力不能混用。原生 Downloads 预览是面向当前体验的入口。

## 原生 Downloads 预览

- 只能通过系统选择器授权构建账号的 Downloads 根目录，不能自行扩大到用户主目录或磁盘。
- bookmark、根目录身份、目录 FD 与路径校验共同限制访问范围；重选或结束访问会释放 scope。
- 只枚举文件名、相对路径、类型、大小和修改时间等元数据；不读取正文、不 hash、不联网。
- 隐藏项、软链接、包、多硬链接、跨卷项会跳过。最多检查 50,000 个目录项，并在目录间
  检查 30 秒预算；这不是严格的超时取消保证。达到限制会显示部分结果。
- 文件名和决定只在进程内存，本地记录只含分类汇总、命令结果与元数据比较计数。
- 应用数据目录权限为 0700，记录为 0600。扫描结果、正文和完整文件列表不会写入日志。
- 记为保留、加入清理预览只改变本轮状态，不授权文件动作；退出或重新选择目录会清除。
- 构建没有 Trash、rename 或 restore 后端，也没有用户文件读写或网络 entitlement。
- 结束访问会比较已扫描文件的路径与身份属性；这不等于正文完整性核验。

建议中的版本、用途和重要性是线索。大小相同不能证明内容相同，时间较早不能证明无用，
候选大小不能被描述成已释放空间。重要资料保护优先于疑似重复与年龄规则。

## 原生 fixture 实验

默认 Rust 构建只能处理构建器登记的临时样本目录，用于 picker、Trash、收据和恢复实验。
它与 Downloads 构建分离。恢复目前仍有真实阻塞：不能放宽身份校验、覆盖同名文件，
或把外部验证器归位样本的结果当作产品恢复成功。

## Python Core 与 React 开发工作台

- 报告默认使用固定 fixture；fake provider 与 consent 流程是离线测试，不调用真实模型。
- 索引、去重、建议与报告不改变源文件；内容 hash 仅属于明确的 Core 去重流程。
- 文件变更集中在 Operations/Quarantine，必须有 plan、preview、confirm、版本与漂移复核。
- 不永久删除；同卷隔离和恢复不覆盖已有文件，失败与部分结果必须保留收据。
- 不解析聊天数据库、不上传文件；不把本地报告模式当作云端读取授权。

开发验证只使用人工样本或测试创建的临时副本。报告问题时移除真实路径、文件名、凭据和内容。
发现漏洞请使用[私密报告入口](../SECURITY.md)。
